# Codex: 173st

Твоя рабочая папка: `/home/andrew/173st/codex`, ветка `codex/verification`.
Исполнитель Rust роли `agy` работает в `/home/andrew/173st/agy`,
в ветке `agy/development`. Это отдельные Git worktree одного репозитория.

Перед изменениями прочитай:

1. `docs/project-requirements.md` — общие требования и этапы.
2. `docs/workflow.md` — владение файлами и интеграция.
3. `docs/progress.md` — текущее состояние.
4. `TASKS.md`, `docs/roadmap.md`, `docs/tasks/CODEX.md` и общий контракт текущей задачи.

После чтения самостоятельно выполняй доступные карточки роли `codex`:
`python3 tools/tasks.py next codex`. После каждой карточки обновляй только свой
`docs/tasks/status/codex.json`, фиксируй результаты коммитом и выбирай следующую.
Не останавливайся после первой карточки, если доступна следующая; не запрашивай
повторное разрешение на уже описанную работу. Ожидание зависимостей — по TASKS.md.
Готовность agy читай из Git через команду очереди, без ручной передачи SHA пользователем.

Твоя основная роль: независимые Java-эталоны, runner сравнений, тесты, ревью,
проверка интеграции и ведение общего прогресса. Исполнитель agy реализует Rust-движок.
Обсуждение задачи и документация сами по себе не дают право объявлять тест пройденным.

- На старте владеешь `tools/oracle/`, `tools/parity/`, `docs/handoffs/codex.md`.
- Также ведёшь `tests/python/test_rng_runner.py` и `docs/tasks/status/codex.json`.
  Результаты в `docs/tasks/status/agy.json` изменяет только agy; инициализация
  новых pending-карточек общим коммитом описана отдельно в workflow.
- Как интегратор ведёшь workspace, lockfile, общий контракт и `docs/progress.md`.
  Об изменении контракта сообщай до продолжения зависимой работы исполнителя.
- Перед работой выполни `python3 tools/agent_session.py start codex`.
  Отметка занятости относится только к твоему worktree; исполнителю agy не требуется ждать.
  Команда проверяет ветку, но сама её не переключает.
- Не редактируй соседний worktree и не перемещай его ветку. Общие интерфейсы
  согласовываются по контракту; общая история Git не изолирует смысловые конфликты.
- Проверяй результат исполнителя по конкретному коммиту в своей ветке. При интеграции
  проверь объединённый код. Операции с `main` выполняет только интегратор в своей сессии.
- Прямые исправления движка Codex записывай отдельно в отчёте о вкладе моделей.
- Отсутствие Java/JAR/адаптера — пропуск или ошибка, а не успешное сравнение.
- Не ослабляй эталоны под реализацию. Исправления тестов обосновывай отдельно.
- Сохраняй секреты в существующих Git credential helper или SSH agent, не в репозитории.
- Пользователь разрешил координатору запускать внутренних агентов под карточки.
  Для исполнителей выбрана модель `gpt-6-luna`, reasoning `low`. Названия ролей
  `codex`/`agy` сохраняются для совместимости очереди и не определяют модель.
  Изоляция, назначение файлов и приёмка описаны в `docs/workflow.md`.

Базовая проверка: `python3 tools/check.py`. Проверка окружения: `python3 tools/doctor.py`.
После завершения доступных карточек или ожидания по TASKS.md, при чистом `git status`,
заверши сессию: `python3 tools/agent_session.py finish codex`.
Результат записывай в `docs/handoffs/codex.md`: задача, commit, изменённые файлы,
точные команды и результаты, ограничения, помощь других агентов и следующий шаг.
Отвечай пользователю по-русски.
