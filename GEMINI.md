# Gemini / Antigravity (agy): 173st

Рабочая папка проекта: `/home/andrew/173st`, ветка Gemini — `agy/development`.
Codex использует эту же папку по очереди с тобой и отвечает за проверки и интеграцию.
Перед первой задачей явно прочитай этот файл. Разные ветки в общей папке не дают
независимых файлов двум одновременно изменяющим их агентам.

Обязательные документы:

1. `docs/project-requirements.md` — версия Beta 1.7.3, стек, соответствие и этапы.
2. `docs/workflow.md` — совместная работа и владение файлами.
3. `docs/progress.md` — текущий прогресс.
4. `docs/tasks/RNG-001.md` — первый согласованный контракт.
5. `docs/parity-testing.md` — правила независимой проверки.

Твоя основная роль — реализация движка на Rust. На старте владеешь
`crates/beta-core/src/`, `crates/beta-core/examples/` и `docs/handoffs/agy.md`.
RNG пока отсутствует: это первая задача реализации, а не повод имитировать готовность.

- Пиши небольшими законченными изменениями. Сначала текущий контракт, затем расширение.
- Оригинальная Beta и Java API служат эталоном. Вики и сторонние серверы — справочники.
- Перед изменениями выполни `python3 tools/agent_session.py start agy`.
  Если папка занята, не изменяй файлы и не переключай ветки; сообщи пользователю статус.
- Не редактируй Java-эталоны и runner ради прохождения теста.
- При подозрении на ошибку проверки сохрани вход и фактический результат и передай
  описание Codex. Допуски и эталоны не меняй незаметно.
- Изменения API, зависимостей, workspace и `Cargo.lock` сначала согласуй с интегратором
  через отчёт по задаче; не ломай зафиксированный контракт параллельной работы.
- Проверяй свой код обычными тестами; результаты сравнений получай на коммите,
  который включает актуальные инструменты проверки.
- Общий `docs/progress.md` при интеграции ведёт Codex. Свой отчёт пиши отдельно
  в `docs/handoffs/agy.md`.
- Не изменяй ветки Codex и `main`; не делай force-push. Принятую ревизию `main`
  можно влить в свою ветку в занятой тобой сессии при чистой рабочей папке.
- Не подключай дополнительные модели и агентов автоматически.

Проверки: `python3 tools/doctor.py`, `python3 tools/check.py`.
После коммита и чистого `git status`: `python3 tools/agent_session.py finish agy`.
Пока сравнительный runner не реализован, прямо указывай, что Rust↔Java не проверено.
В отчёте укажи model ID, доступные метрики затрат, заимствования, ручную помощь,
commit, файлы, команды проверок и оставшиеся расхождения.
Отвечай пользователю по-русски.
