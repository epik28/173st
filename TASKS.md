# Очередь задач Codex и agy

Этот файл — точка входа для самостоятельной работы агентов.
Каждый агент читает свою роль, выбирает доступную задачу и выполняет её до проверяемого
результата. Пользователю не нужно вручную распределять карточки и переносить SHA.

## Роли

| Роль | Рабочая папка и ветка | Ответственность | Карточки |
| --- | --- | --- | --- |
| `codex` | `codex/`, `codex/verification` | Java-эталоны, runner, тесты компаратора, интеграция | [CODEX.md](docs/tasks/CODEX.md) |
| `agy` | `agy/`, `agy/development` | Rust-реализация ядра и probe | [AGY.md](docs/tasks/AGY.md) |

Общий контракт первой задачи: [RNG-001](docs/tasks/RNG-001.md).
Машиночитаемая очередь: [queue.json](docs/tasks/queue.json).
В этот запуск разрешены только перечисленные карточки; после их приёмки следующие
этапы уточняются отдельными контрактами. Не начинать весь движок одним изменением.

## Самостоятельный цикл агента

1. Прочитать файл своей роли (`AGENTS.md` или `GEMINI.md`), общие требования и workflow.
2. Занять только свой worktree через `tools/agent_session.py start <role>`.
3. Выполнить `python3 tools/tasks.py next <role>`.
4. При `ready`/`resume` прочитать указанную карточку и её критерии. Выполнить задачу
   в разрешённых файлах; вести не более одной задачи своей роли одновременно.
5. В **своём** `docs/tasks/status/<role>.json` записать состояние, конкретный результат
   и фактические команды проверок. Обновить свой handoff. Сделать коммит.
6. Ещё раз вызвать `next <role>` и продолжить следующую доступную задачу без
   нового разрешения пользователя. Внутри одного запуска можно выполнить несколько карточек.
7. Если зависимость не готова, записать `waiting` в пользовательский отчёт, но не
   менять чужие статусы и не выдавать её за выполненную. Можно перечитывать очередь
   каждые 15–30 секунд до 5 минут, сообщая прогресс не реже раза в минуту.
   Если новой работы не появилось — завершить локальную сессию с причиной ожидания.
8. При `complete` завершить локальную сессию и сообщить итог. Возобновление
   завершившегося диалога требует нового запуска приложения/сообщения: файлы очереди
   сами не запускают агента и не оплачивают API-вызовы.

Команда выбирает задачу и показывает состояние, а выполняет её сам AI-агент.

## Статусы и передача результатов

Каждая роль меняет только свой файл:

- [status/codex.json](docs/tasks/status/codex.json).
- [status/agy.json](docs/tasks/status/agy.json).

Состояния: `pending`, `in_progress`, `done`, `blocked`.
Для `done` нужны непустые `summary` и `checks` с командами и результатами.
Для `blocked` нужна конкретная причина в `summary`. Наличие статуса `done` — сообщение
исполнителя, не доказательство приёмки: Codex повторно проверяет объединённый код.

Пример элемента после выполнения (значения нужно заменить фактическими):

```json
{"state": "done", "summary": "Что реализовано и что осталось за рамками", "checks": ["команда → фактический результат"]}
```

`tasks.py` читает оба файла из **локальных коммитов соответствующих веток** через Git,
а не из устаревшей копии чужого файла в своём checkout. Незакоммиченные изменения
не объявляют готовность. После каждой карточки обязательно делать коммит.
Не нужно вручную вписывать SHA текущего коммита в сам этот коммит: команда выдаёт
точные `snapshots.codex.commit` и `snapshots.agy.commit`.

Для интеграции сохранить выданный SHA agy и читать отчёт так:

```text
git show <зафиксированный-SHA-agy>:docs/handoffs/agy.md
git show <зафиксированный-SHA-agy>:docs/tasks/status/agy.json
```

Не читать незакоммиченные файлы соседа и не изменять его worktree/ветку.

## Команды

```bash
python3 tools/tasks.py status
python3 tools/tasks.py next codex
python3 tools/tasks.py next agy
```

Для корректного вызова `next`: код `0` — есть задача, `2` — ожидание/блокировка,
`3` — все задачи роли завершены, `1` — ошибка состояния/чтения.
Ориентироваться также на JSON-поле `state`; неверные аргументы CLI печатают usage.
При несовместимых версиях очереди остановить зависимую работу и синхронизировать контракт.
