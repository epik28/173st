# Замечания к текущему viewer

Здесь фиксируются наблюдения из ручного запуска. Они требуют воспроизводимого
разбора; запись не означает, что причина уже найдена или исправлена.

## WORLD-SOURCE-001 — live save изменён после ручной игры

- По состоянию на 2026-11-08 live save в Prism больше не совпадает с исходным
  snapshot, закреплённым в [WORLD-LOAD-001](tasks/WORLD-LOAD-001.md) и
  [REGION-001](tasks/REGION-001.md): `level.dat` и все четыре исходных `.mcr`
  имеют другие размер/ SHA-256. `level.dat_old` теперь также существует.
- Это согласуется с ручным открытием/сохранением мира пользователем. Точные
  текущие хеши сохранены в игнорируемом локальном manifest
  `artifacts/user-world-postplay.sha256`, не добавляются в Git и не переопределяют
  опубликованный эталон. Проверка только читала файлы.
- Старые parity fixtures и их заявленные хеши относятся к прежнему snapshot.
  Live runner, привязанный к исходным хешам, должен отказать на текущем save —
  это корректная защита от сравнения с незакреплёнными данными. Не менять старые
  эталонные хеши автоматически. Для новых тестов использовать ранее созданные
  pinned fixtures/evidence либо отдельно скопировать текущий save и пройти новый
  capture/review.
- После явного запроса пользователя viewer получил отдельный preview baseline из
  ignored workspace-level `artifacts/user-world-postplay.sha256`, общего для
  sibling worktrees. Все пять
  файлов проходят size/SHA и non-symlink checks; приложение и native review
  работают с отдельными copies. Старые fixture hashes не заменялись. На свежем
  capture два native JVM запуска и Rust preview probe совпали побайтно (47
  mapping cases/1,513 neighbors); source hashes были теми же после чтения.
- В текущем запуске viewer прочитал baseline и построил сцену; графическое окно
  не открылось, так как процессу не доступен Wayland compositor. Ранее `xvfb-run`
  показывал `DISPLAY=:99`, но `xdpyinfo` не мог открыть сервер. Viewer построил
  25-chunk scene (334,760 opaque/9,762 water vertices); это подтверждает loader,
  но не визуальное соответствие кадра.

## LEAF-VISUAL-001 — вид кроны изнутри и под острым углом

- Наблюдение: на пользовательском скриншоте от 2026-11-08 крона почти целиком
  закрывает обзор тёмными пересекающимися квадратными слоями листвы; между ними
  остаются тонкие голубые просветы. Нужно сравнить с Beta 1.7.3 при том же
  положении камеры и освещении.
- Проверить: alpha test/cutoff и blend state, winding/culling, native fast/fancy
  leaf mode, face visibility при соседних листьях, UV atlas/mips и свет внутри
  кроны. Не менять отсечение граней наугад: зафиксировать native вызовы и
  сравнить одинаковые кадры с оригиналом.
- Приёмка: отдельные сцены с видом снаружи, изнутри и сквозь край кроны;
  сохранённые native/Rust материалы и камера; тесты на alpha/UV/neighbor
  visibility; визуальный снимок показывает соответствующий оригиналу рисунок
  просветов и яркость без регрессии листвы в обычном ракурсе.
- Пока не известно, является ли это несовпадением с оригиналом или просто
  экстремальным ракурсом внутри кроны; исходная картинка без параметров камеры
  не доказывает конкретную причину.

## FLIGHT-SMOOTH-001 — рывки камеры при полёте

- Статус: исправление внесено и покрыто тестами frame partitions. Перевод
  debug-flight камеры на render interpolation убрал видимый 20 Hz stepping в
  модели контроллера. Пользовательское визуальное подтверждение пока не сделано:
  pinned-world hash guard останавливает viewer на изменённом `level.dat`.
- Проверено: fixed-step движение и mapping controls не менялись; только render
  translation интерполируется по accumulator alpha, yaw/pitch остаются
  немедленными. Одинаковая запись при 20/30/60/144 Hz даёт одинаковые
  состояния на simulation ticks; между ticks камера плавно интерполируется,
  toggle/reset/focus paths синхронизируют прошлую/текущую позицию. Добавлена в
  FLIGHT-SMOOTH-001. Дальше нужна ручная визуальная проверка на закреплённой сцене
  и под нагрузкой; это не native flight parity.

## WATER-VISUAL-001 — прозрачный порядок поверхностей и тёмный проём у берега

- На скриншоте пользователя от 2026-11-09 водяная поверхность выглядит
  неравномерно затемнённой крупными перекрывающимися слоями; у кромки виден
  почти чёрный прямоугольный проём.
- Подтверждённый renderer defect: alpha-blended water quads шли в порядке обхода
  блоков при отключённой записи depth. Добавлена сортировка целых quads
  back-to-front на каждый кадр и regression на порядок/сохранение triangle order.
  Native water geometry и fixture не менялись.
- Чёрный проём пока не классифицирован: он может быть открытым/неосвещённым
  блоком под прозрачной водой, а не пропущенной водяной гранью. Не добавлять
  bottom face вслепую: native FLUID fixture её не задаёт. Для завершения сравнить
  этот берег с оригиналом при том же сохранении и положении камеры.
- Полный pixel smoke в этой среде недоступен: `xvfb-run` снова не смог открыть
  X-сервер. Geometry strict остаётся прежним и не проверяет порядок alpha draw.

## BLOCK-EDIT-001 — задержка при изменении блока и тёмные открытые грани

- На скриншоте пользователя от 2026-11-09 после разрушения блока виден чёрный
  прямоугольный участок; установка и разрушение также сопровождались заметной
  задержкой.
- Задержка имела подтверждённую причину: каждый edit повторно месил всю сцену,
  пересоздавал все GPU buffers и копировал все chunk arrays. Первый локальный
  фикс не убрал полный CPU/GPU merge; пользователь подтвердил, что задержка
  осталась. Текущий кандидат теперь
  пересчитывает только изменённый chunk и его загруженных соседей (включая
  диагональных соседей для углов воды), держит GPU buffers отдельно по чанкам и
  заменяет только буферы этих чанков. Unit tests проверяют neighbor culling,
  replace-chunk, diagonal dirty set и три последовательных удаления. Проверка
  реальной задержки требует GUI smoke на пользовательском компьютере.
- Чёрные грани полностью не приняты как исправленные. Viewer использует
  сохранённые block/sky-light нибблы; позднее добавлен bounded relight в
  `LIGHT-UPDATE-001`, принятый только на пяти native-сценах. Это не подтверждает
  исправление произвольной тёмной поверхности. Новое наблюдение ниже вынесено
  в отдельный контракт с парным сравнением оригинала и Rust.

## LIGHT-UPDATE-002 — иногда появляется лишняя тень рядом с удалённым блоком

- Статус: открыто, сообщение пользователя от 2026-11-09 после bounded relight.
  На новом [скриншоте](bug-reports/light-update-002-after-break.png) видны
  почти чёрные поверхности рядом с землёй и стволами. Пользователь связывает
  появление с ломанием блоков; точный воспроизводимый сценарий ещё не записан.
- Установлены и исправлены две отдельные ошибки: viewer передавал opacity=255
  для всех non-air блоков вместо native таблицы (листва=1, вода=3), а relight
  давал прямой sky-light=15 верхнему прозрачному блоку (для native воды нужно 12).
  Фикс `1c83d2c` проверен по 256 registry rows и 19 light samples трёх native
  synthetic-сцен с полным исходным состоянием. Старые light fixtures проходят.
- Точный случай с пользовательского кадра ещё не воспроизведён. Общая очередь,
  height map, leaf metadata notifications и парные кадры остаются открытыми;
  задача не объявляется полностью исправленной по этим ограниченным тестам.
- В полном V2 corpus выявлены отдельные расхождения света: 2107 клеток при
  установке листвы, 6195 при установке glowstone и 3852 при его удалении.
  Свет в canopy-log и water transitions совпадает по всему тестовому домену;
  native leaf metadata bit8 после удаления ствола ещё отсутствует в Rust.
- Задача: [LIGHT-UPDATE-002](tasks/LIGHT-UPDATE-002.md), высокий приоритет.
  В ней определены native capture, исправление и критерии регрессии.

## MENU-PARITY-001 — временный chooser отличается от оригинального меню

- На текущем пользовательском кадре (2026-11-09) главное меню в однотонном
  синем окне 720×480 с собственными глифами и прямоугольными кнопками. Нет
  вращающегося panorama-фона и native logo; расположение/размеры кнопок и
  масштабирование не совпадают с Beta 1.7.3. Это подтверждённое расхождение,
  не только неподтверждённая pixel parity.
- Список миров также использует временную раскладку; на GUI scale 3 в native
  synthetic запуске пропадает conversion-world при неизменных входных файлах,
  хотя прямой metadata reader возвращает три записи. Исправить UI и отдельно
  установить причину пропавшей записи.
- Задача: [MENU-PARITY-001](tasks/MENU-PARITY-001.md). Конечная цель —
  ресурсы, раскладка, масштабирование и поведение Beta 1.7.3.
- Получены native кадры пустого списка и искусственных metadata-only миров;
  проверены выделение, Return, Cancel/Escape. В синтетическом запуске 1280×720
  пропала строка conversion-world при неизменных входных файлах; direct reader
  возвращает все три записи. Причина ещё не установлена, C01 остаётся открыт.

## WATER-SIM-001 / WATER-MOVE-001 — видимая вода пока не симулируется

- Вода ID 8/9 имеет проверенную геометрию и прозрачный draw pass, но блоки не
  распространяются по тикам. В показанном пользователем береговом кадре форма
  воды остаётся статичной после запуска. Также controller пока использует
  сухую физику: плавание, drag и движение при погружении не реализованы.
- Разделить проверку на world fluid ticks (источники, поток, падение, очередь
  событий) и physics игрока в воде (collision, ускорение, drag, погружение).
  Для обеих частей получить прямые native cases Beta 1.7.3 до реализации;
  сохранения оставить read-only.
- Карточки: [WATER-SIM-001](tasks/WATER-SIM-001.md) и
  [WATER-MOVE-001](tasks/WATER-MOVE-001.md). Текущая геометрия FLUID-001 не
  является доказательством симуляции.

## Очерёдность игровых функций

Есть 36 слотов, hotbar, экран E, иконки четырёх поддержанных ID, загрузка стеков
из сохранения и перенос мышью. Сердца читают сохранённое здоровье, без damage
и regeneration. Впереди расширение каталога/metadata, crafting, armor,
pickup/drop, симуляция здоровья и сохранение изменений. Для каждого пакета
нужны native observations и отдельная приёмка; полного игрового цикла ещё нет.
