# Замечания к текущему viewer

Здесь фиксируются наблюдения из ручного запуска. Они требуют воспроизводимого
разбора; запись не означает, что причина уже найдена или исправлена.

## WORLD-SOURCE-001 — live save изменён после ручной игры

- По состоянию на 2026-11-08 live save в Prism больше не совпадает с исходным
  snapshot, закреплённым в [WORLD-LOAD-001](tasks/WORLD-LOAD-001.md) и
  [REGION-001](tasks/REGION-001.md): `level.dat` и все четыре исходных `.mcr`
  имеют другие размер/ SHA-256. `level.dat_old` теперь также существует.
- Это согласуется с ручным открытием/сохранением мира пользователем. Точные
  текущие хеши сохранены в игнорируемом локальном manifest
  `artifacts/user-world-postplay.sha256`, не добавляются в Git и не переопределяют
  опубликованный эталон. Проверка только читала файлы.
- Старые parity fixtures и их заявленные хеши относятся к прежнему snapshot.
  Live runner, привязанный к исходным хешам, должен отказать на текущем save —
  это корректная защита от сравнения с незакреплёнными данными. Не менять старые
  эталонные хеши автоматически. Для новых тестов использовать ранее созданные
  pinned fixtures/evidence либо отдельно скопировать текущий save и пройти новый
  capture/review.

## LEAF-VISUAL-001 — вид кроны изнутри и под острым углом

- Наблюдение: на пользовательском скриншоте от 2026-11-08 крона почти целиком
  закрывает обзор тёмными пересекающимися квадратными слоями листвы; между ними
  остаются тонкие голубые просветы. Нужно сравнить с Beta 1.7.3 при том же
  положении камеры и освещении.
- Проверить: alpha test/cutoff и blend state, winding/culling, native fast/fancy
  leaf mode, face visibility при соседних листьях, UV atlas/mips и свет внутри
  кроны. Не менять отсечение граней наугад: зафиксировать native вызовы и
  сравнить одинаковые кадры с оригиналом.
- Приёмка: отдельные сцены с видом снаружи, изнутри и сквозь край кроны;
  сохранённые native/Rust материалы и камера; тесты на alpha/UV/neighbor
  visibility; визуальный снимок показывает соответствующий оригиналу рисунок
  просветов и яркость без регрессии листвы в обычном ракурсе.
- Пока не известно, является ли это несовпадением с оригиналом или просто
  экстремальным ракурсом внутри кроны; исходная картинка без параметров камеры
  не доказывает конкретную причину.

## FLIGHT-SMOOTH-001 — рывки камеры при полёте

- Статус: исправление внесено и покрыто тестами frame partitions. Перевод
  debug-flight камеры на render interpolation убрал видимый 20 Hz stepping в
  модели контроллера. Пользовательское визуальное подтверждение пока не сделано:
  pinned-world hash guard останавливает viewer на изменённом `level.dat`.
- Проверено: fixed-step движение и mapping controls не менялись; только render
  translation интерполируется по accumulator alpha, yaw/pitch остаются
  немедленными. Одинаковая запись при 20/30/60/144 Hz даёт одинаковые
  состояния на simulation ticks; между ticks камера плавно интерполируется,
  toggle/reset/focus paths синхронизируют прошлую/текущую позицию. Добавлена в
  FLIGHT-SMOOTH-001. Дальше нужна ручная визуальная проверка на закреплённой сцене
  и под нагрузкой; это не native flight parity.

## Очерёдность игровых функций

`ITEMS-001` закрыл только native-backed data API: 36 слотов и hotbar с четырьмя
проверенными item IDs. Следующие отдельные этапы — видимый hotbar/inventory GUI,
перенос предметов мышью, pickup/drop, затем health HUD и survival state. Для
каждого нужны собственные native observations и контракты; нынешний viewer не
имеет полного игрового цикла.
