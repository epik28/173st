# Подробные этапы Beta 1.7.3

Это план до полноценной игры. Исполнять автоматически можно карточки из
[queue.json](tasks/queue.json); остальные пункты требуют контракта с API, входами
и приёмкой, который готовит Codex перед началом соответствующего пакета.
Наличие пункта в этом документе не означает готовность функции.

RNG-001, RNG-002, CHUNK-001 и NBT-001 приняты в `main`. Текущий пакет —
[REGION-001](tasks/REGION-001.md), пять карточек для чтения настоящего McRegion.

## Общий цикл каждого пакета

Codex фиксирует контракт, готовит независимый эталон и проверку компаратора.
agy параллельно реализует Rust и диагностический probe. Codex проверяет конкретный
коммит agy, объединённую сборку и реальные сравнения, затем принимает результат в
`main`. Исправления внутри того же контракта входят в работу исполнителя и не
требуют нового назначения пользователем; порядок описан в [TASKS.md](../TASKS.md).

Для каждого принятого пакета сохраняются входы, происхождение эталона, хеши,
команды, охват и известные расхождения. Обычный тест, Java API, оригинальный клиент,
оригинальный сервер и проверка формата — разные виды доказательств.

| --- | --- | --- | --- |

| 0.2 RNG-002 — принят | `set_seed`, bounded int, long, boolean, float, double; смешанные вызовы | Java API; rejection sampling, знаки, биты float, состояние после reseed | 13227 операций совпали точно, RNG-001 продолжает проходить |
| 0.3 JAVA-001 — план | Нужные числовые преобразования Java, UTF-16 hash строки, координатная арифметика | Прямые Java-выражения, Unicode, переполнения, NaN/бесконечности для применимых операций | Каждая используемая операция имеет независимые граничные примеры |
| 0.4 GAME-ORACLE-001 — план | Только необходимые интерфейсы для следующих probes | Адаптеры реальных классов клиентского JAR, таблица obfuscated имён и хешей | В отчёте доказан вызов оригинального метода, а не переписанной формулы |

JAVA-001 и MATH-001 закрывают зависимости конкретных потребителей: не нужно
задерживать чтение файлов или окно ради ещё не используемых функций.
Для сетевых тестов позже понадобится отдельный оригинальный серверный JAR.

## Этап 1 — настоящее сохранение без графики

| Пакет | Что делает agy | Что проверяет Codex | Условие приёмки |
| --- | --- | --- | --- |
| 1.1 CHUNK-001 — принят | Координаты, массивы 16×128×16, ID и три nibble-массива | Границы, отрицательные координаты, порядок байтов и оригинальный nibble-класс | 4182 операции совпали; нет порчи соседнего nibble |
| 1.2 NBT-001 — принят | Теги 0–11, big-endian, modified UTF-8, строгие лимиты | 5250 live cases с настоящими `ij`/`nu`, отдельно wire extensions и отличия native | NBT parity в согласованной общей области; исходный оригинал и расхождения описаны |
| 1.3 REGION-001 — в очереди | Read-only McRegion `.mcr`, header/sectors, bounded zlib и raw NBT payload | Native reader Beta 1.7.3 и 704 непустых chunk slots из локального сохранения | Совпали наличие, timestamp, compression и raw chunk bytes; источник не изменён |
| 1.4 WORLD-LOAD-001 — план | `level.dat`, spawn, время, seed, измерение, состояние игрока и tile entities | Снимок данных исходного сохранения и перечень неподдержанных тегов | Headless загрузчик выдаёт проверяемую сводку участка; исходный мир не меняется |

NBT и Region сначала читают данные. Запись вводится отдельно после проверки
сохранности неизвестных тегов. Зависимости для сжатия фиксируются интегратором
перед параллельной реализацией; версии нельзя выбирать независимо двум агентам.

**Первый визуальный рубеж — VIEW-001**, а не завершение всех механик.
До его закрытия не начинаем AI мобов, редстоун и собственную генерацию мира.
Базовый кадр сначала собирается понятно; оптимизация геометрии должна сохранять
текстурирование и освещение. UI и графические зависимости вводятся отдельным
согласованным изменением workspace.

## Порядок открытия следующих контрактов

После REGION-001 Codex готовит WORLD-LOAD-001, затем VIEW-001. Параллельно
перед их потребителями уточняет JAVA-001,
GAME-ORACLE-001 и MATH-001. Новые API/зависимости фиксируются до начала работы agy.
Это план продолжения, а не разрешение двум агентам независимо расширять queue.json.
Пользователю достаточно запускать очередь роли; утверждать каждое исправление
внутри уже согласованного контракта не требуется.
