# Подробные этапы Beta 1.7.3

Это план до полноценной игры. Исполнять автоматически можно карточки из
[queue.json](tasks/queue.json); остальные пункты требуют контракта с API, входами
и приёмкой, который готовит Codex перед началом соответствующего пакета.
Наличие пункта в этом документе не означает готовность функции.

RNG-001, RNG-002, CHUNK-001, NBT-001, REGION-001, WORLD-LOAD-001, VIEW-001,
MATH-001, JAVA-001, GAME-ORACLE-001, MOVE-001, COLOR/LEAF/LIGHT и FLUID-001 приняты.
Viewer показывает воду ID 8/9 отдельным прозрачным проходом; simulation и lava
остаются за границами поддержки. PLAYER-SAVE-001 добавил ограниченное чтение
поддержанных предметов из `Player.Inventory`, но не изменение или сохранение.
Общая экспертная оценка текущего среза — около33%; следующие игровые механики
требуют нового контракта. HUD показывает сохранённое здоровье, но не симулирует
урон или лечение. Инвентарь поддерживает ограниченный mouse transfer, но ещё не
умеет world drop, crafting, armor, item use или сохранение изменений.

## Общий цикл каждого пакета

Codex фиксирует контракт, готовит независимый эталон и проверку компаратора.
agy параллельно реализует Rust и диагностический probe. Codex проверяет конкретный
коммит agy, объединённую сборку и реальные сравнения, затем принимает результат в
`main`. Исправления внутри того же контракта входят в работу исполнителя и не
требуют нового назначения пользователем; порядок описан в [очереди задач](tasks/queue.json)
и правилах [совместной работы](workflow.md).

Для каждого принятого пакета сохраняются входы, происхождение эталона, хеши,
команды, охват и известные расхождения. Обычный тест, Java API, оригинальный клиент,
оригинальный сервер и проверка формата — разные виды доказательств.

текстурирование и освещение. Графические зависимости закреплены контрактом VIEW-001
до начала параллельной реализации.
