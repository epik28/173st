# MATH-001 — Beta 1.7.3 MathHelper parity

Статус: контракт открыт после VIEW-001. Цель — перенести малый набор общих
игровых числовых функций на Rust и проверять результаты настоящего клиента,
чтобы последующие движение и генерация не опирались на приблизительные формулы.

## Независимый оригинал

Эталон — локальный клиентский JAR Beta 1.7.3, SHA-256
`af1fa04b8006d3ef78c7e24f8de4aa56f439a74d7f314827529062d5bab6db4c`.
Вызовы делаются reflection непосредственно к `in`, class SHA-256 фиксируется в
fixture audit. Сопоставление подтверждено bytecode: `a(F)F` sine, `b(F)F`
cosine, `c(F)F` sqrt(float), `a(D)F` sqrt(double)->float, `d(F)I` floor(float),
`b(D)I` floor(double), `e(F)F` abs(float), `a(DD)D` abs-max,
`a(II)I` floor-div, `a(String)Z` null-or-empty. Имена здесь относятся только к
закреплённому JAR и не являются публичным Rust API.

Нельзя использовать Rust-результат, формулу из стороннего порта или сохранённый
вывод как источник ожидаемого результата. Java вызывает методы оригинального
класса; таблица из 65 536 значений инициализируется самим классом. Зависимость
от JDK и платформы записывается в отчёт. Сравнение float/double — по raw bits.

## Rust API и probe

`beta_core::math` предоставляет `sin(f32)`, `cos(f32)`, `sqrt_f32(f32)`,
`sqrt_f64_to_f32(f64)`, `floor_f32(f32)`, `floor_f64(f64)`, `abs_f32(f32)`,
`abs_max_f64(f64,f64)`, `floor_div_i32(i32,i32) -> Result<i32, MathError>` и
`is_null_or_empty(Option<&str>)`. Ошибка деления на ноль явная; для
`i32::MIN / -1` поведение должно соответствовать контракту проверки, а не panic.
Никаких зависимостей добавлять не нужно.

Probe — `crates/beta-core/examples/math_probe.rs`, протокол TSV:

```text
case_id<TAB>operation<TAB>arguments
```

Float/double аргументы передаются как фиксированные hex raw bits; `null` —
отдельный аргумент для string predicate. Выход — `case_id<TAB>raw_result`, где
floating point записан hex bits, integer decimal, boolean `0`/`1`. Ошибочный
синтаксис, переполнение диапазона, дубликат ID и неизвестная операция дают
ненулевой код и диагностику в stderr. Весь ввод ограничен контрактными лимитами.

## Корпус и обязательные поведенческие сценарии

Codex C01 генерирует сохранённый детерминированный корпус и ожидаемый вывод только
через оригинальный Java oracle. Включить:

- sin/cos около всех квадрантов, оборотов, отрицательных углов, signed zero,
  бесконечностей/NaN, больших конечных значений и границ перехода LUT-индекса;
- не менее 4096 воспроизводимых конечных углов и случаи, проверяющие каждый
  индекс LUT либо документированное доказательство полного покрытия индексов;
- sqrt по нулю, субнормальным, отрицательным, максимальным, бесконечным и NaN
  значениям; double-to-float overflow/underflow;
- floor непосредственно вокруг отрицательных/положительных целых, нуля,
  i32 границ и NaN/бесконечности согласно Java cast semantics;
- abs для обоих нулей, отрицательных значений и NaN; abs-max с равными числами,
  знаками, нулями и NaN;
- floor-div для знаковых комбинаций, точных/неточных частных, `MIN`, `MAX`,
  делителей ±1 и ошибок деления на ноль;
- null/empty/non-empty строки, включая Unicode и пробелы.

Добавить отдельно размеченные invalid protocol inputs. В отчёте показать количество
операций по методу и набор покрытых LUT индексов. Самопроверка Java oracle должна
доказать, что вызваны `in` и закреплённые методы; никакой Rust parity в C01 не
заявлять.

## Роли

- C01: original MathOracle, bytecode/class/JAR audit, детерминированный corpus и
  независимая повторяемость на двух запусках.
- C02: `math` parity runner, строгий comparator, saved-report/protocol review и
  синтетические мутации; предыдущие suites сохраняются.
- A01: чистый Rust API и тесты крайних значений по контракту.
- A02: TSV `math_probe`, ошибки/лимиты и тесты протокола.
- C03: интеграция точного agy SHA, full checks, прежние live suites, math parity,
  saved review, обновление progress/roadmap/estimate и принятие в main.

## Приёмка

- `python3 tools/check.py`, `cargo test --all-targets --locked --offline` и doc tests
  проходят.
- `python3 tools/parity/run.py math --strict` запускает оригинал и Rust на одном
  corpus и сравнивает каждую строку точно; отсутствующий процесс не даёт pass.
- Повторный Java запуск даёт идентичный output и fixture; ошибки/timeout,
  повреждение протокола, удаление/перестановка/изменение строки обнаруживаются.
- Отчёт сохраняет JAR/class/oracle/probe/input/output hashes, версии Java/Rust,
  точные ревизии и first mismatch. Источник и JAR не копируются в репозиторий.
- Ограничения по IEEE-754, JDK и целочисленному переполнению перечислены явно.
