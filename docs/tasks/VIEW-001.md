# VIEW-001 — первый графический Beta 1.7.3 viewer

Статус: контракт зафиксирован; реализация ещё не начата.

## Цель и границы

Открыть read-only сохранение Beta 1.7.3 в отдельном Rust-приложении, показать
базовую местность и дать свободно облететь её. Это первый видимый срез движка,
а не полный клиент и не заявление о полной визуальной parity. Сцена ограничена
фиксированным квадратом 5×5 чанков вокруг spawn из `level.dat`; загружаются только
уже существующие чанки. Исходный мир, Java JAR и игровые ресурсы только читаются.

Первая версия рисует непрозрачные полные кубы, для которых поведение оригинального
клиента подтверждено C01. Она строит наружные грани и отбрасывает грань, если
соседний блок тоже подтверждён как полный непрозрачный куб. Используются реальные
ID/meta/свет из сохранённых массивов и соответствующие стороны atlas UV, найденные
по вызовам оригинального клиента. Все остальные block states считаются
неподдержанными и перечисляются в диагностике, а не подменяются похожей моделью.
Прозрачность, листья/растения/нестандартные формы, вода, сущности, небо, туман,
биомная окраска, анимации, HUD, физика и редактирование относятся к следующим
пакетам.

## Входы и неизменяемые данные

- Native reference: локальный клиентский JAR Beta 1.7.3, SHA-256
  `af1fa04b8006d3ef78c7e24f8de4aa56f439a74d7f314827529062d5bab6db4c`.
- Текстура `terrain.png` читается из JAR/настроенного локального ресурса;
  ожидаемый оригинальный PNG SHA-256
  `9e32336c83732193a20d0f942ae8aa1186ae01231245b5e83659ce6e9d3511cf`.
  Бинарный ресурс в Git не добавлять. Ошибка пути/hash должна быть явной.
- Тестовый world берётся из настроенного локального Prism save. Для native и Rust
  запусков используются раздельные run-specific копии. Реальные миры, JAR и
  извлечённые классы/ресурсы не коммитить.
- Фиксированный корпус: 25 координатных слотов вокруг spawn, полученных через
  WORLD-LOAD-001. Отсутствующий чанк остаётся absent; исходная копия не изменяется.

## Архитектура

- Workspace crates: `beta-view` (чистые структуры сцены/меша/камеры и CPU-тесты)
  и `beta-viewer` (bin, файловый адаптер, окно и GPU). Существующий `beta-core`
  остаётся независимым от окна/GPU.
- Зафиксировать в общем `Cargo.toml` до параллельной реализации точные версии:
  `winit = 0.30.13`, `wgpu = 30.0.1`, `image = 0.25.10` (только PNG),
  `bytemuck = 1.25.2` (derive), `glam = 0.34.2`, `pollster = 0.4.0`;
  сохранить `Cargo.lock`, проверить Linux Vulkan/GLES и Wayland/X11 features.
  Новые crates не добавлять без зафиксированного обоснования и обновлённого lock.
- Safe Rust; `unsafe` запрещён. У GPU vertex/index/depth/texture ресурсов явные
  лимиты и корректная обработка resize/surface lost/close.
- Окно 1280×720, resizable; глубина включена, atlas sampling nearest, без
  сглаживания текстур. Камера perspective 70°, near 0.05, far 128 блоков.
  Свободный полёт: WASD, Space/Ctrl по вертикали, Shift ускоряет, мышь поворачивает,
  Esc отпускает захват; управление не меняет мир. Начальная позиция — выше и в
  стороне от spawn с видом на поверхность; конкретные координаты записать в
  конфиге тестовой сцены, чтобы повторить кадр.
- Загрузка/мезинг не выполняются каждый кадр. На экран выводятся счётчики чанков,
  видимых граней и неподдержанных состояний (окно или stderr).

## Независимый oracle и parity

C01 исследует bytecode и вызывает реальные native методы/путь клиента: свойства
block render type/opacity, mapping ID+metadata+face в terrain atlas, ориентацию
сторон и shading для поддерживаемых блоков. Oracle обязан журналировать class/JAR
hash и конкретные native call counts. Таблицы из beta-wiki или сторонних проектов
могут помочь найти методы, но не являются ожидаемыми значениями.

На основе закреплённых 25 чанков сформировать компактную детерминированную матрицу
уникальных реально встречающихся `(block_id, metadata, face, neighbor_state)` и
результат native методов. Синтетические boundary/malformed cases хранить отдельно
от live parity. Rust `view_probe` выдаёт deterministic TSV для CPU mesh: координаты
вершин, индексы/порядок граней, ID/meta/face, UV/tile и световые значения в
зафиксированном формате. Runner сравнивает строки точно; float-поля передавать
битами, если original native path возвращает float. Не округлять и не расширять
допуск без записи native evidence.

CPU parity проверяет mapping/геометрию, но сама по себе не доказывает пиксельную
идентичность GPU кадра. C03 сохраняет собственный screenshot viewer для ревью,
сцену/camera/config/adapter hashes и явно перечисляет не измеренные визуальные
различия. Сравнение с original screenshot допустимо только при зафиксированных
драйвере, разрешении, настройках и доказанной одинаковой камере.

## Задачи и разделение ролей

1. `VIEW-001-C01` (Codex): native исследование, pinned 25-slot copied snapshot,
   scene/camera fixture, atlas SHA/provenance, live + отдельно synthetic corpus.
2. `VIEW-001-C02` (Codex): independent Java oracle wrapper, strict runner/comparator,
   report/protocol verifier и mutation/invalid-input tests. Начальный strict run
   обязан показать `not_implemented` до Rust probe.
3. `VIEW-001-A01` (agy): core `beta-view` scene/mesh/camera types и CPU meshing;
   сравнение с зафиксированным C01 корпусом только после C02 runner commit.
4. `VIEW-001-A02` (agy): `view_probe` TSV и отдельный `beta-viewer` bin на
   winit/wgpu, чтение локальных world/resources, окно/камера/текстуры/отрисовка.
5. `VIEW-001-C03` (Codex): чистый snapshot, CPU parity, старые регрессии,
   запуск/снимок сцены, проверка read-only инвариантов, отчёт и приёмка в main.

Все задачи получают явные зависимости в `queue.json`; C01 и crate pin/lock должны
быть закоммичены до выдачи A01. C02 и A01 могут идти параллельно после C01.

## Приёмка

- `python3 tools/check.py`, `cargo test --all-targets --locked --offline`, fmt,
  check, clippy `-D warnings`, doc проходят.
- Старые parity группы `rng`, `rng-extended`, `chunk`, `nbt`, `region`, `world`
  проходят на принятом чистом Rust snapshot.
- `view --strict` совпадает со всеми строками закреплённого live corpus; protocol,
  report hash, Java source/JAR/class hash, copies и payloads проверены. Мутации
  mismatch/report и некорректный протокол отвергаются.
- Приложение стартует из настроенного локального save, показывает загруженную
  местность и реагирует на resize/управление камеры; unsupported counts видны;
  invalid config/resource возвращает диагностируемую ошибку.
- Хеши исходных файлов save и JAR до/после одинаковы; нет записи в исходник,
  коммита приватного ресурса, локальных артефактов или декомпилированных файлов.
- C03 отделяет проверенные CPU данные от визуального smoke test и фиксирует
  известные пробелы. После этого VIEW-001 можно принимать, но полная визуальная
  parity остаётся открытой до следующих пакетов.

## Вне объёма

Полная загрузка мира, streaming за 5×5, генерация/тикающие блоки, физика игрока,
редактирование, сохранение, сеть, моды и производительное сравнение с оригиналом.
Оптимизация здесь ограничена не созданием внутренних граней поддержанных opaque
кубов и отсутствием повторного meshing в render loop; общей победы FPS не заявлять.
