# HUD-001 — native first-person hotbar and health overlay

## Goal

Give the existing read-only world viewer its first fixed first-person HUD layer:
the native Beta 1.7.3 hotbar frame/selection, heart row at full health, and centered
crosshair. This is a render-only presentation slice. It does not add item sprites,
inventory screen, health simulation, damage, hunger, survival tick, or input to
change selected slot.

## Sources and scope

- Reference client: `../.local/minecraft/client-b1.7.3.jar`, read-only.
- Native GUI resources: `gui/gui.png` and `gui/icons.png`; verify exact resource
  bytes and dimensions from the pinned JAR. The viewer may extract these exact
  entries in memory after verifying the archive hash; do not copy assets into the
  game/repository or modify the JAR.
- Native layout comes from the pinned Beta `GuiIngame` bytecode. Keep source/class
  hashes and the relevant method signatures in the audit. Do not infer native
  layout from modern Minecraft.
- Existing viewer still loads its world through the pinned local-save guard. A
  mismatch must stop before copying or opening the user's changed Prism save.

## Contract

- HUD is drawn in screen space after opaque and fluid world passes, with depth
  testing disabled for HUD geometry.
- Anchor the hotbar and health using the original scaled-resolution dimensions,
  integer centers and `GuiIngame` offsets. Preserve the native 256×256 atlas UVs
  and alpha; do not stretch atlas pixels. Very small viewports follow vanilla
  clipping behavior.
- Initial state is selected hotbar index 0 and health 20/20. Draw nine empty
  slots, native selection frame, ten full hearts, and the native crosshair.
- Use the original GUI texture resources, not hand-drawn replacements. Keep
  nearest sampling and pixel-aligned screen-space coordinates.
- No player survival state is implied by the fixed full-health display. Document
  this limitation in viewer help/progress.

fixtures, Python tests, queue, status, or shared docs. Do not weaken the existing

### HUD-001-C02 — integration and acceptance (Codex)

Review exact A01 commit; run native resource/layout verifier and relevant tests,

## Acceptance boundaries

Tests must establish atlas source/hash and layout constants, UV bounds, viewport
anchor calculations for several aspect ratios/sizes, and that HUD rendering is
ordered after the world passes. No screenshot pixel parity or gameplay health
parity is claimed by this slice.
