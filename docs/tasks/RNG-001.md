## API Rust

Предлагаемый публичный интерфейс этой задачи:

```rust,ignore
use beta_core::java_random::JavaRandom;
let mut random = JavaRandom::new(seed); // seed: i64
let value: i32 = random.next_int();
```

Этот API реализован в ветках разработки. Другие методы RNG
в эту задачу не входят. Целочисленное переполнение при переносе Java явно определять.

## Вход и выход

Оба probe читают UTF-8 из stdin. Формат входа — TSV, один случай на строку:

```text
case_id<TAB>seed_i64_decimal<TAB>count
```

Пустые строки и строки с `#` в начале пропускаются. Seed разбирается как знаковый
64-битный integer; count — положительный integer, верхняя граница для обоих probe
100000. ID непустой, содержит только ASCII буквы, цифры, `_` и `-`; ID уникальны
в одном входе. Неверный вход даёт ненулевой код выхода, диагностика идёт в stderr.

Перед каждым случаем создаётся новый RNG с указанным seed. Результаты:

```text
case_id<TAB>zero_based_index<TAB>signed_i32_decimal
```

Порядок случаев и результатов сохраняется, окончания строк LF. Логи в stdout
не добавляются. Выход сравнивается точно. Базовые входы:
`tests/fixtures/rng/next-int.tsv`, включая минимальный и максимальный `i64`.

## Запуск после реализации

```text
cargo run --locked --offline -p beta-core --example rng_probe
python3 tools/parity/run.py rng --strict
```

Команды доступны в объединённой ветке Codex. Runner компилирует Java и Rust
один раз на запуск, затем подаёт каждой стороне тот же сохранённый вход.
Build-логи отделены от данных. Java-эталон вызывает настоящий `java.util.Random`;
LCG вручную в Java не реализуется. Зависимости crates.io для этой задачи не нужны.

## Приёмка

1. Все 96 значений fixture совпадают точно, обе стороны успешно завершились.
2. Формируется отчёт с seed, входами, выходами, хешами, версиями и точной областью
   покрытия по `docs/parity-testing.md`. Область — Java RNG API, не генерация мира.
3. Намеренная замена одного значения в копии Rust-выхода обнаруживается сравнением:
   отдельный регрессионный тест компаратора выдаёт mismatch. Реальный отчёт остаётся
   результатом сравнения реальных процессов; подменённые данные отдельно помечаются.
4. Отсутствующая Java, неуспешная компиляция, timeout и неверный ввод дают ошибку.
5. `python3 tools/check.py` проходит на объединённом коммите.
6. Нельзя подменять Rust-probe вызовом Java или встроенным списком эталонных ответов.

Следующая задача после приёмки: расширение RNG по методам и смешанным вызовам.
